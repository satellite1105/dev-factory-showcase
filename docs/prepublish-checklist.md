# 公開前チェックリスト

> 記述時点: 2026-10。内容は非公開の内部概要資料(v2 系)から概念レベルで書き下ろしたもので、内部仕様は今後変わる可能性があります。

## 使い方

公開する版を作者自身が確認するための一覧です。同梱時点では、確認項目も最終承認欄も未チェックです。自動チェックの成功だけで Public 化を承認したことにはなりません。

公開用の新しい履歴の検査、GitHub 上の Mermaid 描画の目視確認、人手確認と最終承認、公開前チェックの再実行、Public 化、直後の報告窓口の有効化は、[公開ゲート](public-release-gate.md)の順序で作者自身が行います。途中で問題が見つかった場合は Public 化を止め、修正した版を再確認してください。

## 自動チェック

次のコマンドはすべて、この公開用リポジトリのルートから実行します。ここに示すのは実行手順であり、実行済みの結果ではありません。

```sh
python3 scripts/prepublish_check.py
python3 scripts/prepublish_check.py --history
python3 scripts/check_docs.py
python3 scripts/test_prepublish_check.py
python3 scripts/test_check_docs.py
```

通常の公開前チェックに加え、`--history` でコミット履歴も調べます。履歴検査には git が必要です。最初のコミットより前の結果だけでは公開する履歴の確認にならないため、コミット後にも実行してください。文書チェックは相対リンク、Mermaid の静的な構造、検証ステータスなどの整合を調べます。自己テストは検査道具の確認用で、公開内容そのものの点検も別に必要です。

履歴検査はコミットメッセージ本文も対象とし、AI セッション URL、内部 URL、セッション情報の trailer、既存の個人情報・秘密情報カテゴリを調べます。正常な `Co-Authored-By` 表記そのものは違反扱いしません。パターンに一致しない内部情報までは検出できないため、過去のコミットメッセージを含む履歴全体を人手でも確認してください。

履歴上の author と committer のメールは、最初のコミットも含めて両方とも許可ドメインで検査します。

公開前チェックは `ERROR` があれば失敗します。終了コードが成功でも `WARN` や検査の省略を示す `INFO` を読み、未確認の範囲を残したまま承認しないでください。特に GitHub 上の Mermaid 描画は静的検査だけでは確認できません。

外部スキル名の本文検出はハイフンを含む名前だけが対象で、ハイフンなしの名前はディレクトリ名でのみ検出します。モデル ID や内部の名前には汎用パターンがなく、ローカルの禁止語リスト(git 対象外)に登録した語だけが検出対象です。`PASS` は混入がないことの証明ではないため、人が公開対象を確認してください。

### ローカル専用の検査リスト

`scripts/denylist.local.txt` に、公開物へ含めたくない案件名、個人を特定できる表記などを、手元で一行に一語ずつ記入します。空行と `#` から始まる行はコメントとして扱います。短すぎる語には警告が出るため、警告も確認してください。`scripts/denylist.example.txt` は書式の見本であり、実際の禁止語リストの代わりにはなりません。

`scripts/skill-names.local.txt` には、混入を調べる外部 skill の名前を、手元で一行に一名ずつ記入します。空行と `#` から始まる行は除外されます。名前のリストが空だと、その名前に基づく検査は働きません。公開する文書やコードには個別名を書きません。

どちらも git 対象外のローカル専用ファイルです。存在すれば通常の実行時に自動で読み込まれます。内容を画面、実行ログ、レビュー資料や公開物へ貼り付けず、コミット対象に含めないでください。明示指定する場合は次を使います。

```sh
python3 scripts/prepublish_check.py --denylist scripts/denylist.local.txt --skill-names scripts/skill-names.local.txt
```

長文の転載を照合するには、作者が権限を持つ手元の資料を `--reference` で指定します。次のプレースホルダは手元で置き換えてください。資料そのものをリポジトリにコピーする必要はありません。照合元を指定しなければ長文一致の検査は省略されるため、通常実行の成功を転載なしの証拠にはしません。

```sh
python3 scripts/prepublish_check.py --reference "<手元の照合資料>"
```

## Public 化前に人が確認する項目

- [ ] 公開予定の全ファイルを読み、氏名、メール、ホームパス、ハンドル名など、意図しない個人情報がないことを確認した。
- [ ] 実案件名、略称、クライアント名、所属を特定できる記述がないことを確認した。
- [ ] API キー、トークン、認証情報などの秘密の値が本文、コード、例、ログに含まれていないことを確認した。
- [ ] 第三者の非公開資料や、許諾を確認できない文章を含めていないことを確認した。
- [ ] 内部の資料、手順、役割定義、雛形を転載せず、公開向けに書き下ろしていることを確認した。
- [ ] 安全装置の実ファイル名、設定値、承認処理の内部など、公開しない実装詳細が含まれていないことを確認した。
- [ ] スクリーンショットや画像を使わない方針を確認し、画面の写り込みや画像ファイルの混入がないことを確認した。
- [ ] 図は自作の Mermaid のみで、他者の図、画像、ロゴを流用していないことを確認した。
- [ ] 外部 skill は同梱・再配布せず、その本文や個別名も公開物に含めていないことを確認した。
- [ ] ローカル専用の禁止語・外部 skill 名リストを準備し、git 対象外であり、公開対象へ混入していないことを確認した。
- [ ] 公開前チェック、文書チェック、自己テストを実行し、失敗、警告、検査省略の内容を確認した。
- [ ] 権限のある手元の資料との長文一致検査を行い、転載の疑いが残っていないことを確認した。
- [ ] git の公開予定履歴を確認し、過去の追加・削除内容にも個人情報や非公開情報が残っていないことを確認した。コミット前なら、コミット後に改めて確認する。
- [ ] 過去のコミットメッセージを含む履歴全体に非公開情報が無いことを確認した。セッション URL・内部 URL など、自動検査のパターンに一致しない情報も人手で確認した。
- [ ] コミットの author / committer の名前が公開に適し、メールが GitHub の正しい noreply アドレスであることを作者が履歴で確認した。正しいアドレスが確認できない場合は仮設定せず、最初のコミット後にも履歴上の値を確認する。
- [ ] README の主張、事例の説明、検証ステータスの根拠と限界が一致し、未検証の項目を検証済みとしていないことを確認した。
- [ ] 実際の実装・検証と、説明用に再構成した記録の区別を確認した。
- [ ] 商標の帰属、非公式の個人プロジェクトである旨、出典をリンクだけで示す方針を確認した。
- [ ] 決定済みのライセンス(コード MIT / 文書 CC BY 4.0)と適用範囲が LICENSE・LICENSE-docs.md・本文で一致することを作者が確認した。
- [ ] 決定済みの著作権者表記(2026 satellite1105)が LICENSE・LICENSE-docs.md・本文で一致し、公開予定の履歴にも旧表記との不整合がないことを作者が確認した。
- [ ] 公開対象がこのリポジトリの成果物に限られ、内部の作業記録やローカル専用資料を含んでいないことを確認した。
- [ ] 公開ゲートに沿って Private の段階で履歴チェックと Mermaid 描画の目視確認(P07)を行い、承認後も公開する版でチェックを再実行し、不備があれば Public 化を止めることを確認した。
