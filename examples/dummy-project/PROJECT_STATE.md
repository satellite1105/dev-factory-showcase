## GOAL_CONTRACT

以下の8項目は、この例の完了条件を一か所で確認するための要約です。

| 項目 | この例で固定した内容 |
| --- | --- |
| objective | 入力を集計し、上位の語を選んだ形式で表示する CLI と実行案内を揃える。 |
| done_when | spec の [S1]〜[S4] が成立し、必須要件に未解決の指摘がなく、最新のレビューが合格している。 |
| verification | README の3例、そこで案内する unittest discover、空入力 CSV の再現確認、REVIEW の採点と指摘の照合を行う。 |
| constraints | 標準ライブラリだけを使い、ネットワークへの接続や外部公開を行わない。 |
| allowed_files | このサンプル内の wordfreq/・tests/ の Python ファイルと README.md・spec.md・PROJECT_STATE.md・REVIEW.md。これは架空の開発範囲の記述であり、現在の編集権限を与えるものではない。 |
| budget | 基盤の既定に従い、デバッグは最大3ラウンド、レビューは最大3回とする。 |
| blocked_stop_condition | 上限まで直しても未達が残る場合、重大な制約違反がある場合、または人の判断なしには安全に進めない場合は blocked にして判断を求める。 |
| last_verified_evidence | 架空の修正後の版 example-after と REVIEW の2回目を対応させ、全テスト成功・CSV 見出し・使用例一致を確認済みと置く。実在する版や独立レビューの証跡ではなく、この記載を実案件の完了証拠には使えない。 |

完了条件、実行済みの検証、最新の証拠、レビュー合格、制約の順守、停止条件への非該当をすべて確認してから完了とする設計です。この例の `completed` は、その条件を満たしたと想定しています。(検証ステータス: 設計済み(未検証) / V11)
