# wordfreq のレビュー例

> 記述時点: 2026-10。内容は非公開の内部概要資料(v2 系)から概念レベルで書き下ろしたもので、内部仕様は今後変わる可能性があります。
> この文書は説明用の再構成で、実際の実行記録ではありません。2回の採点、指摘、修正履歴、対象の版は架空です。コードとテストの実際の作成経緯は [README](README.md) を参照してください。

## 採点方法

要件の充足に0.4、テスト・検証に0.3、コードの品質に0.2、文書に0.1を掛けて合計し、小数第2位に丸めます。合格には0.85以上に加え、`passed: true`、空の `critical_errors`、計算の一致、必須要件・完了条件・重大な制約の未達がないことを要します。点数だけでは合格になりません。(検証ステータス: 実機検証済み / V06)

## 1回目: 不合格という例

対象を架空の修正前の版 `example-before` とします。空入力の CSV 見出しが欠けると仮定した指摘は1件です。現在のコードでこの不具合が起きるという主張ではありません。

```json
{
  "round": 1,
  "target_version": "example-before",
  "scores": {
    "requirements": 0.8,
    "tests": 0.7,
    "code_quality": 0.8,
    "docs": 0.8
  },
  "total_score": 0.77,
  "passed": false,
  "critical_errors": [],
  "findings": [
    {
      "id": "CSV-EMPTY",
      "severity": "major",
      "requirement": "F4 / S2",
      "summary": "架空の修正前は、空入力の CSV に見出し行が出なかった",
      "reproduction": "dummy-project で printf '' | python3 -m wordfreq --format csv を実行する",
      "expected": "word,count と改行を出力する",
      "actual": "修正前の想定では標準出力が空だった",
      "fix_direction": "データ行がなくても CSV 見出しを出力し、空入力の回帰テストを確認する"
    }
  ]
}
```

手計算:

```text
0.8 × 0.4 + 0.7 × 0.3 + 0.8 × 0.2 + 0.8 × 0.1
= 0.32 + 0.21 + 0.16 + 0.08
= 0.77
```

点数が基準に届かず、[spec](spec.md) の [F4]・[S2] も満たさないため、不合格とします。`critical_errors` が空でも、この必須要件の指摘が残る間は合格にしません。

## 修正と再現確認の例

| 指摘 | 修正方針 | 修正後に確かめること |
| --- | --- | --- |
| CSV-EMPTY | 見出しを出す処理を、データ行があるかどうかの分岐から外す | 空入力でも `word,count` と改行が出て、CSV の通常入力と他形式のテストも成功する |

ここでの修正は架空の経過です。現在の `format_rows([], "csv")` は見出し行を返し、空入力の回帰テストも実装されています。README の例3は、その現在の CLI を実行して得た出力です。実際にこのタスクでコードを修正したわけではありません。

## 2回目: 合格という例

架空の修正後の版 `example-after` に対象を揃え、初回の指摘を解消し、影響するテストと使用例を再確認したと想定します。以下は独立した実レビューの報告ではありません。

```json
{
  "round": 2,
  "target_version": "example-after",
  "scores": {
    "requirements": 0.9,
    "tests": 0.9,
    "code_quality": 0.85,
    "docs": 0.8
  },
  "total_score": 0.88,
  "passed": true,
  "critical_errors": [],
  "findings": [],
  "resolved_findings": ["CSV-EMPTY"]
}
```

手計算:

```text
0.9 × 0.4 + 0.9 × 0.3 + 0.85 × 0.2 + 0.8 × 0.1
= 0.36 + 0.27 + 0.17 + 0.08
= 0.88
```

0.85以上で計算も一致し、`passed` は true、重大な誤りと未解決の指摘は空です。必須要件の未達もないと想定し、合格の例とします。この0.88を実際のリポジトリの品質評価には使いません。
