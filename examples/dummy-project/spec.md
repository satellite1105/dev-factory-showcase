# wordfreq の要件定義例

> 記述時点: 2026-10。内容は非公開の内部概要資料(v2 系)から概念レベルで書き下ろしたもので、内部仕様は今後変わる可能性があります。
> この文書は説明用の再構成で、実際の実行記録ではありません。依頼文と要件整理は架空です。コードとテストの実際の作成経緯は [README](README.md) を参照してください。

## 架空の依頼文

「文章に出てくる語の回数を数える CLI を作ってください。ファイルと標準入力を使えて、上位の語を text・csv・json で表示したいです。」

## 目的

同じ入力から同じ集計結果を得られ、ターミナルでの確認にも別のプログラムへの受け渡しにも使える小さな道具を用意します。

## 必須要件

- [F1] ファイル指定がない場合と `-` の指定時は標準入力を読み、UTF-8 のファイルを複数指定した場合は内容を合算する。
- [F2] 語を抽出して数える。既定では `casefold()` で大文字小文字をまとめ、`--no-lowercase` なら表記を保持する。数字と語中の半角アポストロフィも扱う。
- [F3] 頻度の降順、同数なら語の昇順で並べる。`-n` は1以上とし、既定で上位10語を返す。
- [F4] `text` はタブ区切り、`csv` は `word,count` の見出し付き、`json` は `word` と `count` を持つオブジェクトの配列で返す。空入力は順に空文字列、見出し行のみ、`[]` とする。
- [F5] `--stopwords FILE` で除外語を読み込む。1行1語とし、空行と `#` から始まる行を無視する。除外語の照合では大文字小文字を区別しない。

## 非機能要件

追加のライブラリは導入せず、Python の標準ライブラリだけを使います。集計処理と CLI の入口を分け、正常系だけでなく空入力と入力エラーをテストします。読めないファイルは標準エラー出力に通知して終了コード1を返し、不正な引数は終了コード2とします。

## 成功条件

- [S1] [F1]・[F2]・[F3] を、標準入力・単一ファイル・複数ファイル・同数の語・大小文字のテストで確認できる。
- [S2] [F4] の各形式が期待する構造を持ち、空入力の CSV でも見出しが残る。
- [S3] [F5] の除外語、読めない入力、不正な表示数のテストが成功する。
- [S4] [README](README.md) の使用例を再現でき、そこに記載した discover コマンドで全テストが成功し、[REVIEW](REVIEW.md) の合格条件を満たす。

## 前提と仮定

- 対象は Python 3 のローカル CLI とする。入力の文字コードは UTF-8 とする。
- 語の境界は正規表現による文字のまとまりで決める。日本語の連続した文字列を文法上の単語へ分けることは求めない。
- 表示数が語の種類数を超えた場合は、存在する語だけを返す。
- JSON の末尾改行は必須にしない。空入力時の CSV 見出しは必須とする。
- これは説明用の要件設定であり、実際に利用者がこの依頼をしたという意味ではない。

## スコープ外

画面付きアプリ、ネットワーク接続、形態素解析、永続的な集計データの保存、入力全体をメモリに載せず処理する方式は扱いません。
